# SPEC. VOLTA

Техническое описание первой версии. Если PRD говорит «что видит человек», этот файл говорит «как это собрано».

## Стек

| Слой | Выбор | Зачем |
| --- | --- | --- |
| Сайт и админка | Next.js (App Router) + TypeScript | Один проект на витрину и `/admin` |
| Стили | Tailwind CSS v4 | Токены ниже задаются в CSS-переменных |
| Анимация | `motion/react` | Плавные появления и реакция на нажатие. Импорт только из `motion/react` |
| Иконки | `@phosphor-icons/react`, толщина 1.75 | Одна семья на весь сайт |
| Шрифт | Manrope, через `next/font` | Геометрический гротеск под тёмную витрину. Inter не берём |
| Данные | PostgreSQL + Prisma | Заказы и пользователи нельзя держать в файле |
| Вход | Auth.js, провайдеры Credentials и Google | Почта+пароль и Google в одной сессии |
| Пароль | bcrypt | Хеш, не открытый текст |
| Корзина на клиенте | Zustand с записью в `localStorage` | Гость не теряет товары при обновлении страницы |
| API | REST `/api/v1/...` | Тот же адрес потом вызовут Expo и Telegram |

Серверные экшены не заменяют API. Витрина ходит в `/api/v1`, чтобы не писать второй бэкенд под телефон.

Переменные окружения, файл `.env.example` без секретов:

```
DATABASE_URL=
AUTH_SECRET=
AUTH_GOOGLE_ID=
AUTH_GOOGLE_SECRET=
ADMIN_EMAIL=
PAYMENT_PROVIDER=mock
YOOKASSA_SHOP_ID=
YOOKASSA_SECRET_KEY=
```

`PAYMENT_PROVIDER=mock` в первой версии. Значение `yookassa` зарезервировано и в этой версии отвечает ошибкой «оплата ещё не подключена», пока нет отдельной задачи на боевой вызов.

## Дизайн-система

Чтение брифа: тёмная витрина техники для покупателя с телефона, язык скрина (уголь, белый текст, фото на всю плитку), сетка главной как bento, плотность каталога выше, чем у лендинга.

Настройки плотности: вариативность 6, движение 5, плотность 6. Главная чуть свободнее каталога. Админка плотнее и почти без анимации: это рабочий стол, не витрина.

Одна тема на весь сайт: тёмная. Светлой версии нет, переключателя темы нет. Секции не становятся бежевыми посередине страницы.

| `--bg-elevated` | `#16191F` | Плитки товаров, поля, выпадающее меню |

### Форма

Одно правило на весь сайт:

- плитки и карточки: 16px;
- поля ввода: 10px;
- кнопки и поле поиска: полная капсула;
- аватар: круг.

Тени почти не нужны: тон задаёт рамка `--line` и разница фонов. Если тень есть у выпадающего меню, цвет `rgb(0 0 0 / 0.45)`, размытие 24px.

### Типографика

Одна семья, Manrope.

| Роль | Размер | Вес |
| --- | --- | --- |
| Баннер на главной | 40px, с 1024px 56px | 700, межбуквенный −0.03em |
| Заголовок страницы | 32px / 40px | 700 |
| Название товара в сетке | 16px | 600 |
| Цена | 18px | 700 |
| Текст | 16px, высота строки 1.5 | 400 |
| Мелкая подпись | 13px | 500 |

Заголовки баннеров на главной можно набирать прописными, как на скрине. Остальной интерфейс: обычная капитализация, «В корзину», не «В КОРЗИНУ». Над заголовками секций не ставим мелкие подписи капителью. Заголовок секции сам по себе понятен: «Сейчас смотрят», «Хиты недели».

Длина строки текста на информационных страницах не шире 65 символов.

### Сетка

Контейнер: `max-w-[1280px]`, боковые поля 16px на телефоне, 24px с 768px, 32px с 1024px.

Главная, bento. На ширине от 1024px:

```
+---------------------------+----------+
|                           | акция 2  |
|   большой баннер          +----------+
|                           | акция 3  |
+---------------------------+----------+
| товар | товар | товар | товар       |
+------------------+-------------------+
| промо на 7 кол.  | промо на 5 кол.   |
+------------------+-------------------+
| товар | товар | товар | товар       |
+--------------------------------------+
```

12 колонок, промежуток 12px. Большой баннер занимает 8 колонок и высоту двух правых плиток. Правые плитки делят оставшиеся 4 колонки по вертикали. Нижний промо-ряд: 7 и 5 колонок, не две равные половины.

На ширине до 767px всё в одну колонку, в том же порядке: большой баннер, акция 2, акция 3, товары по одному, промо друг под другом. С 768 до 1023: баннер на всю ширину, две акции в ряд, товары по две.

Каталог не bento. Это ровная сетка: 1 / 2 / 4 колонки на тех же порогах. Карточка товара: фото 1:1, название, цена, старая цена если есть, бейдж «−N%» если есть старая цена.

Пустых клеток в bento нет. Три баннера и ряды товаров. Если баннер в админке выключен, сетка перестраивается, дырка не остаётся: два баннера становятся «большой + один», один баннер на всю ширину.

### Движение

Каждая анимация что-то сообщает: порядок появления, нажатие, смена числа в корзине.

- Появление блоков главной: opacity 0→1 и сдвиг на 12px, 500ms, кривая `cubic-bezier(0.16, 1, 0.3, 1)`, задержка соседей 50ms. Один раз.
- Кнопка в активном состоянии: `scale(0.98)`.
- Счётчик корзины: пружина, stiffness 400, damping 28.
- Выезд мобильного меню и мини-корзины: сдвиг по X, 280ms, та же кривая.
- Смена фото в карточке: crossfade 200ms.

`prefers-reduced-motion: reduce` отключает сдвиги и пружины, оставляет мгновенную смену состояния. Не вешаем слушатель `window` `scroll`. Не анимируем ширину и высоту.

### Картинки

Фото товаров и баннеров прямоугольные, с `object-fit: cover`. Пока нет своих фото, допустимы заглушки `https://picsum.photos/seed/volta-<slug>/<w>/<h>`. У каждой есть запас размера, чтобы сетка не прыгала. Первое фото товара и большой баннер грузятся с приоритетом.

Аватар по умолчанию: файл `public/avatars/default.jpg`, портрет, не иконка человека. В шапке круг 36px, в кабинете 96px.

## Карта сайта

Шапка одна на витрине. Слева слово VOLTA (ссылка на главную). Дальше текстовые пункты: Каталог, Акции, Магазины, Доставка. Справа поиск, сравнение, избранное, корзина со счётчиком, вход. На ширине до 1023px текстовые пункты уходят в меню-панель слева, в шапке остаются логотип, поиск и корзина. Высота шапки 64px, не выше 72px. На десктопе пункты в одну строку.

«Каталог» открывает панель категорий, не уводит сразу на пустую страницу. Клик по категории ведёт в раздел.

## Каталог

Категории первого уровня:

1. Смартфоны и гаджеты: смартфоны, планшеты, часы, наушники.
2. Ноутбуки и компьютеры: ноутбуки, мониторы.
3. Телевизоры и аудио: телевизоры, саундбары.
4. Крупная техника: холодильники, стиральные машины, кондиционеры.
5. Кухня и дом: пылесосы, чайники, аэрогрили.

В семенах по 2 товара на листовую категорию, всего 24. Цены целые рубли, от 1 990 до 89 990. У части есть старая цена выше текущей. Остаток от 0 до 12. Один товар в каждой крупной ветке с остатком 0, чтобы было видно состояние «нет в наличии».

Список товаров:

- сортировка: сначала новинки, дешевле, дороже, по скидке;
- фильтры: цена от и до, бренд, только в наличии, только со скидкой;
- бренд это строка у товара, отдельной таблицы брендов нет;
- 12 товаров на страницу, внизу номера страниц;
- поиск по названию и бренду, без морфологии. Запрос короче 2 символов не ищет.

Карточка:

- галерея, главное фото крупно, остальные снизу в ряд, на телефоне свайп не обязателен в v1, хватает точек;
- цена, старая цена, размер скидки в процентах округление вниз;
- наличие: «В наличии N шт.» или «Нет в наличии»;
- количество и «В корзину»;
- характеристики: список пар «название / значение», не таблица на 20 строк с двумя рамками. Группы: «Основное», «Память и экран» или «Габариты», по смыслу товара, 4-8 строк;
- кнопки «В сравнение» и «В избранное»;
- блок «Похожие»: 4 товара той же листовой категории, без текущего.

Сравнение: таблица характеристик, товары колонками. На телефоне колонки с горизонтальной прокруткой, первая колонка названий липкая. Пустое сравнение объясняет, что добавлять товары из каталога.

## Корзина и заказ

Позиция: товар, количество, цена на момент добавления не фиксируется. В корзине всегда текущая цена. В заказе цена фиксируется копией.

Гость: корзина в `localStorage`, ключ `volta-cart`. Вошедший: серверная корзина. При входе, если в обоих местах есть один товар, количества складываются и обрезаются остатком.

Нельзя положить больше, чем есть на складе. Кнопка «+» останавливается на остатке.

Оформление:

- телефон, обязателен, маска не блокирует вставку;
- имя получателя, по умолчанию из профиля;
- способ: курьер или самовывоз;
- для курьера: улица, дом, квартира, комментарий;
- для самовывоза адрес точки показан, поля улицы нет;
- итог: товары, доставка, сумма;
- кнопка «Подтвердить заказ».

После подтверждения остаток уменьшается в той же транзакции, что и создание заказа. Если остатка уже нет, заказ не создаётся, человек видит, какой товар кончился.

Статусы заказа: `pending_payment`, `confirmed`, `shipping`, `done`, `cancelled`. На экране по-русски: ждёт оплату, подтверждён, в доставке, выполнен, отменён.

Отмена человеком в v1 нет. Отменяет администратор. При отмене остаток возвращается. Повторная отмена остаток не удваивает.

Оплата: `paymentStatus` = `unpaid`. Текст на успехе: «Заказ № принят. Оплата картой появится позже, сейчас ничего не списано.»

## Вход и кабинет

Регистрация: имя, почта, пароль, повтор пароля. Пароль от 8 символов, есть буква и цифра. Ошибки под полями, не одним общим абзацем. Почта в нижнем регистре, уникальна.

Вход: почта и пароль. Плюс кнопка «Войти через Google».

Если Google вернул почту, которая уже есть:

- пользователь с паролем получает привязку Google к тому же аккаунту;
- второй пользователь не создаётся.

Пользователь только из Google не имеет хеша пароля. В кабинете вместо «Сменить пароль» форма «Задать пароль»: новый и повтор, без старого. После этого работает и пароль, и Google.

Смена пароля у обычного аккаунта: текущий, новый, повтор. После смены сессия остаётся, старый пароль больше не подходит.

5 неудачных входов по одной почте за 15 минут: ответ «Слишком много попыток, подождите». Счётчик в таблице `LoginAttempt`.

Аватар: jpg, png, webp, до 2 МБ. Хранится в `public/uploads/avatars/<userId>.<ext>`, старый файл этого пользователя удаляется. В базе путь. Если файла нет, показывается `/avatars/default.jpg`.

Роль: `customer` или `admin`. Администратор это пользователь, чья почта совпала с `ADMIN_EMAIL` в момент создания. Роль видна в админке, повысить другого человека можно там же.

Сессия Auth.js, cookie httpOnly, 30 дней.

Страницы `/account` и `/checkout` без сессии уводят на `/login?next=<путь>` и после входа возвращают назад. `/admin` без роли администратора отвечает 404, не 403, чтобы не подтверждать, что раздел существует.

## Админка

Та же тёмная палитра, без bento и без входных анимаций секций. Слева список: Сводка, Заказы, Товары, Категории, Баннеры. На ширине до 767px список сверху, горизонтальный скролл.

Сводка: четыре числа. Заказы сегодня, заказы «ждёт оплату», товаров нет в наличии, пользователей. Числа из базы, не зашиты.

Заказ: состав, контакты, сумма, выбор статуса. Смена на «отменён» возвращает остаток.

Товар: форма с подписями над полями. Обязательны название, цена, остаток, категория, хотя бы одно фото URL в v1 (загрузка файла товара не обязательна: поле URL, чтобы не строить хранилище картинок дважды; аватар при этом файлом, потому что это личные данные пользователя, а не витрина). Slug из названия латиницей, можно поправить. Галочка «Показывать на сайте».

Категории: имя, родитель, порядок. Удаление категории с товарами запрещено, сообщение какое.

Баннеры: ровно 3 записи в базе, создаются сидом. Поля: заголовок, подзаголовок до 12 слов, ссылка внутри сайта, URL картинки, включён. Слоты: `hero`, `side-top`, `side-bottom`.

## API `/api/v1`

Ответы JSON. Ошибка: `{ "error": "текст по-русски" }` и подходящий HTTP-код. Успех списка: `{ "items": [], "page": 1, "pages": 3 }`.

Авторизация веба: cookie сессии. Заголовок `Authorization: Bearer` в v1 принимается только заглушкой задачи T19 и до неё отвечает 401. Контракт заголовка описан заранее, чтобы Expo не придумывал другой.

| --- | --- | --- |
| POST `/auth/register` | гость | Создаёт пользователя |
| POST `/auth/login` | гость | Сессия, тело email и password |
| POST `/auth/logout` | сессия | Выход |
| GET `/me` | сессия | Профиль без хеша |
| PATCH `/me` | сессия | Имя |
| POST `/me/password` | сессия | Смена или установка пароля |
| POST `/me/avatar` | сессия | multipart файл |
| GET `/categories` | все | Дерево |
| GET `/products` | все | Фильтры query: category, brand, min, max, stock, sale, sort, page, q |
| GET `/products/:slug` | все | Товар, фото, характеристики, 4 похожих |
| GET `/cart` | сессия | Позиции и суммы |
| PUT `/cart` | сессия | Заменяет позиции массивом `{ productId, qty }`, так гостевая корзина сливается одним запросом |

## Оплата, как её подключать потом

Интерфейс в коде, одна реализация `mock`:

```
createPayment(order) -> { status: "unavailable" }
handleWebhook(body, headers) -> не вызывается в v1
```

Когда дойдут до ЮKassa (тестовый магазин):

1. `POST https://api.yookassa.ru/v3/payments` с Basic-авторизацией shopId и секретного ключа.
2. Заголовки `Idempotence-Key: order.number`, сумма строкой с двумя знаками (`"12990.00"`), валюта `RUB`, `capture: true`, `confirmation.type: redirect`, `return_url` на `/checkout/success`.
3. В заказ пишется `paymentId` и `paymentStatus=pending`.
4. Вебхук `payment.succeeded` переводит заказ в `paid` только если сумма совпала. `payment.canceled` ставит `failed`, сам заказ не удаляет.
5. Секрет вебхука проверяется. Без проверки статус не меняется.

Это описание стыка, не задача на реализацию в первой очереди. В TASKS за это отвечает T18, и она ограничена заглушкой и комментарием в коде со ссылкой на этот раздел.

## Telegram и Expo, стык

Не пишем приложения. Фиксируем правила, чтобы API не пришлось ломать:

- Базовый URL один: `/api/v1`.
- Телефон и Mini App не пользуются cookie. Для них следующая задача выдаст access token.
- Telegram: Mini App пришлёт `initData`. Сервер проверит HMAC-SHA256 по токену бота, как в документации Telegram (`WebAppData`). Из `initData` возьмёт `id` пользователя Telegram и найдёт или создаст `User` с полем `telegramId`. Поля в схеме уже можно добавить nullable: `telegramId BigInt unique`, `expoPushToken`. В v1 они пустые и нигде в UI не показываются.
- Expo: тот же JSON. Картинки абсолютными URL. Даты ISO 8601.
- Пагинация и имена полей из таблицы выше не переименовывать без версии `/api/v2`.
