# TASKS. VOLTA

Четыре слоя, строго по очереди. Внутри слоя задачи тоже сверху вниз.

1. Сайт. Витрина, кабинет, админка. Данные в браузере.
2. База. Те же экраны пишут в PostgreSQL, появляется API.
3. Telegram Mini App.
4. Мобильное приложение на Expo.

Отметки:

- `[x]` сделано
- `[ ]` предстоит

После закрытия задачи поставь `[x]` и сдвинь «сейчас» на следующую строку без отметки.

Общие правила на задачи сайта:

- Тексты на русском, без слоганов, которых нет в PRD.
- Цвета, радиусы и ширины только из SPEC.
- Экран проверяется на 390 и 1440. Фокус с клавиатуры виден.
- `prefers-reduced-motion` убирает сдвиги.

## Слой 1. Сайт

### [x] S01. Каркас

Сделано: Next.js (App Router), TypeScript, Tailwind v4, Manrope через `next/font`, `motion`, `@phosphor-icons/react`, Zustand. Prisma, Auth.js и PostgreSQL не ставили. `npm run dev` открывает тёмную страницу со словом VOLTA.

### [x] S02. Оболочка

Сделано: токены из SPEC, кнопки, поля, шапка, подвал. Шапка на 1440 в одну строку и не выше 72px. На 390 логотип и значки не наезжают.

### [x] S03. Меню каталога

Сделано: «Каталог» от 1024 открывает панель с деревом. До 1023 панель выезжает слева, закрывается крестиком, затемнением и Escape. Сдвиг через `motion`, при reduced motion сразу. Фокус не уходит под панель.

### [x] S04. Главная

Сделано: bento из SPEC (`hero`, `side-top`, `side-bottom`), без пустой клетки. Ряды «Новинки» и «Хиты недели»: 1 / 2 / 4 колонки. Нижний ряд 7/5, на узком экране столбиком. Появление секций один раз, сдвиг 12px.

### [x] S05. Учебные товары в браузере

Сделано: каталог, баннеры, пользователи, корзины и заказы в `localStorage` ключом `volta-shop-v2`. 58 товаров с витрин Ташкента (Samsung, Xiaomi, Artel, Honor и др.), фото в `public/products`. В каждой ветке первого уровня один товар с остатком 0. Администратор `admin@volta.shop` / `Admin1234`, пароль как SHA-256.

### [x] S06. Каталог, фильтры, поиск

Сделано: `/catalog`, `/catalog/[slug]`, `/search`. Фильтры и сортировка в query-строке. 12 товаров на страницу. Пустой результат и скелетоны. «В наличии» прячет нулевой остаток, поиск по куску названия находит товар, страница 2 открывается по URL.

### [x] S07. Карточка товара

Сделано: галерея, цена, старая цена, скидка округлением вниз, остаток, характеристики, похожие. «В корзину» не превышает остаток. «В сравнение» максимум 4. Скрытый товар открывается как ненайденный.

### [x] S08. Корзина

Сделано: `/cart`. Значок в шапке ведёт сюда, мини-корзины нет. Количество, удаление, сумма по текущей цене. Пустая корзина по SPEC. Обновление страницы не стирает корзину гостя.

### [ ] S09. Регистрация и вход ← сейчас

`/login`, `/register`. Правила пароля и ошибки под полями из SPEC. 5 неудач за 15 минут по одной почте. Кнопка «Войти через Google» видна и пишет «Вход через Google не настроен». Настоящего запроса к Google нет. `next` в адресе возвращает назад, только если путь начинается с `/` и не с `//`.

### [ ] S10. Корзина после входа

Гостевая корзина сливается с корзиной аккаунта. Одинаковые товары складываются и обрезаются остатком. В другом браузере той же корзины нет: общее хранилище появится вместе с базой. В этом браузере после выхода и входа товары на месте.

### [ ] S11. Кабинет

`/account`: имя, почта без смены, пароль, аватар. Файл jpg/png/webp до 2 МБ, хранится в браузере. Если файла нет, картинка `/avatars/default.jpg`. После смены пароля старый не пускает. Битый или слишком большой файл не затирает прежнее фото.

### [ ] S12. Избранное и сравнение

Избранное у вошедшего, гостя уводит на вход и возвращает к товару. `/compare` из локального списка, на 390 таблица скроллится внутри себя.

### [ ] S13. Заказ

`/checkout` только после входа. Курьер 490 ₽, бесплатно от 15 000 ₽, самовывоз 0 ₽. Подтверждение списывает остаток, чистит корзину, даёт номер `V-1001` и дальше. Две попытки купить последнюю штуку: вторая получает ошибку по товару, остаток не уходит в минус. На успехе текст, что деньги не списаны. Кнопки «Оплатить» нет.

### [ ] S14. История заказов

`/account/orders` и карточка заказа. Чужой номер не открывается. Сумма в заказе не меняется, если потом поменять цену товара. В кабинете пункты: профиль, корзина, заказы.

### [ ] S15. Админка: заказы

`/admin` для роли admin. Остальные видят «страница не найдена». Сводка: заказы сегодня, ждут оплату, нет в наличии, пользователи. Смена статуса. Отмена возвращает остаток один раз.

### [ ] S16. Админка: товары и категории

Создание и правка. Товар, который уже есть в заказе, не стирается, только снимается с витрины. Категорию с товарами удалить нельзя. Новая цена видна на сайте после обновления страницы.

### [ ] S17. Админка: баннеры

Три слота правятся в админке, главная их читает. Выключенный слот не оставляет дырку, правило сетки из SPEC.

## Слой 2. База

Начинать, когда S01-S17 закрыты. Экраны не перерисовывать, меняется источник данных.

### [ ] D01. PostgreSQL и Prisma

Схема из SPEC, миграция, сид теми же товарами и администратором. Пароль администратора bcrypt. `.env.example` без секретов.

### [ ] D02. API каталога

`GET /api/v1/categories`, `/products`, `/products/:slug` по SPEC. Страницы каталога и главная читают API, а не `localStorage`.

### [ ] D03. Пользователи и Auth.js

Регистрация, вход, смена пароля, аватар файлом на сервере. Google: если ключей нет, кнопка по-прежнему говорит, что вход не настроен. Если ключи есть, вход создаёт или находит пользователя по почте. Лимит 5 попыток хранится в `LoginAttempt`.

### [ ] D04. Корзина, избранное, заказы

Маршруты из SPEC. При входе гостевая корзина уходит в `PUT /cart`. Заказ создаётся транзакцией со списанием остатка. История читает сервер. После этого слой сайта больше не источник правды для аккаунта.

### [ ] D05. Админка на базе

Те же формы пишут в Prisma. Сводка считается запросами.

### [ ] D06. Стык оплаты

`POST /api/v1/payments` отвечает 501. Провайдер `mock` не вызывает `api.yookassa.ru`. В комментарии у провайдера ссылка на раздел SPEC «Оплата».

### [ ] D07. Контракт для приложений

`docs/API.md`: маршруты, примеры JSON корзины и заказа, абсолютные URL картинок. `Authorization: Bearer` пока отвечает 401 с текстом «Токен приложения ещё не включён». Cookie веба работает как раньше.

## Слой 3. Telegram Mini App

Начинать после D07.

### [ ] M01. Бот и оболочка

Отдельное приложение `apps/mini`. Открывается внутри Telegram, снизу не перекрывается кнопками Telegram. Тема берёт тёмные токены VOLTA, не стандартную белую тему Telegram.

### [ ] M02. Вход через initData

Сервер проверяет подпись `initData` по токену бота. Находит или создаёт пользователя с `telegramId`. Выдаёт сессию для `/api/v1`. Подделанный `initData` не пускает.

### [ ] M03. Витрина

Главная, каталог, поиск, карточка. Корзина и оформление заказа. Кабинет: имя из Telegram, заказы, без смены пароля. Аватар из Telegram, пока человек не загрузил свой.

### [ ] M04. Админка не входит

Mini App только для покупателя. Ссылка на админку внутри Telegram не открывается.
